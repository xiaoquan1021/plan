# XQProject Lifecycle

## Purpose

Define the top-level project object that owns project identity, source directory, save state, and the root `XQScene`.

## Owns

Future source files:

```text
src/core/XQProject.h
src/core/XQProject.cpp
src/core/XQProjectId.h
tests/core/XQProjectLifecycleTest.cpp
```

## Inputs

- Empty project skeleton.
- Source boundary rules.
- Native project directory opener.

## Outputs

- One in-memory `XQProject` per opened project directory.
- Stable project id, display name, root path, modified state, and `XQScene`.

## Rules

- `XQProject` is an XQ-owned domain object, not a wrapper around MITK, CTK, Qt project models, or SimVascular project classes.
- The project root may be a SimVascular-style directory such as `<acceptance-project>`, but the loaded object is still a native XQ project.
- Opening a project directory creates a complete project object graph before UI panels attach to it.
- No old plugin lifecycle, extension registry, or workbench activation event is allowed in this layer.

## Data Contract

`XQProject` stores:

```text
ProjectId id
std::filesystem::path rootDirectory
std::string displayName
ProjectOrigin origin
ProjectLoadStatus loadStatus
XQScene scene
bool modified
std::vector<ProjectDiagnostic> diagnostics
```

`ProjectOrigin` values:

```text
EmptyXQProject
SimVascularDirectory
XQNativeDirectory
```

## Implementation Contract

Public API surface:

```text
ProjectId
ProjectOrigin
ProjectLoadStatus
ProjectDiagnostic
XQProject::createEmpty(rootDirectory, displayName)
XQProject::openExisting(rootDirectory)
XQProject::scene()
XQProject::markModified()
XQProject::markSaved()
XQProject::close()
```

Dependency boundary:

```text
allowed: C++ standard library, XQScene, XQ ids and diagnostics
not allowed: Qt widgets, VTK renderers, MITK/CTK/BlueBerry, project UI classes
```

## Step Plan

- [ ] Define `ProjectId` as a value type generated by XQ, not by an external library.
- [ ] Define `XQProject` with root path, display name, origin, scene, modified state, and diagnostics.
- [ ] Define lifecycle operations: `createEmpty`, `openExisting`, `markModified`, `markSaved`, and `close`.
- [ ] Make project opening return a project object, not directly mutate the workbench.
- [ ] Add tests for empty project creation and direct opening of `<acceptance-project>`.

Required cases:

## Acceptance

- A project can be created without Qt widgets.
- A project can exist before VTK renderers are created.
- `<acceptance-project>` maps to one `XQProject` with one root `XQScene`.

## Failure Repair

If project state is split between UI widgets, VTK objects, and IO readers, repair this document and move the state into `XQProject` or `XQScene`.
